# Multi-project deployment (migration)

Platform: 8080 private; School: 8081 private behind School ingress; Internal Tool: 8082 private behind its own ingress; Swagger: 8090 development only. Use independent credentials for each project and separate PostgreSQL databases. Existing Platform DATABASE_URL and AUDIT_DATABASE_URL remain authoritative. School and Internal Tool open independently owned pools at startup using SCHOOL_DATABASE_URL and INTERNAL_TOOL_DATABASE_URL respectively. Internal Tool has explicit business migrations; School business migrations are not implemented yet. The nginx example is not a complete TLS configuration. No production deployment is enabled by this change.

Generate local School workload credentials from `backend/projects/school` with `GOWORK=off go run ./cmd/workload-config /absolute/path/to/new-private-directory`. Source the resulting platform.env in the Platform process environment and school.env in School's process environment. Never commit these files. The generator intentionally grants no global Foundation access. School readiness remains false until end-to-end verification is implemented.

## Database provisioning

Provision separate databases and login roles for Platform, School and Internal Tool; a shared PostgreSQL server is acceptable. Revoke CONNECT from PUBLIC on each project database and grant it only to its owner and explicitly authorized migration roles. Use non-superuser application roles without CREATEDB, CREATEROLE or membership in another project's roles. Keep each process's environment isolated. Platform continues to use DATABASE_URL (and optional AUDIT_DATABASE_URL); consumers must not receive either. School and Internal Tool require PostgreSQL URIs with explicit host, database and user; use TLS for remote servers. The pool verifies the connected database and user against the URI, but separate environment values alone cannot enforce server-side privileges: verify ACLs during provisioning. /health/database is a private dependency probe, not application readiness. No database is created or migrated automatically.

## Build ownership

No root Go workspace is required. The Platform, School, Internal Tool and Core modules build with GOWORK=off. Platform annotation generation remains provider-owned and consumes Core through a local module replacement; School and Internal Tool generate SDKs from service-owned specifications. The local replacement is an intentional monorepo development dependency, not a published release. Each project can be built and tested via its own entrypoint. Root Makefile convenience commands do not share database credentials or start another project's process. Frontend package-manager files are scoped to frontend/. Published Core and npm packages, remote dependency verification and separate deployable repository checkouts are not yet complete.
