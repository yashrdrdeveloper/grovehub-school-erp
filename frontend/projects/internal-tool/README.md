# Internal Tool frontend

Independent React/Vite application at http://127.0.0.1:4174, proxying only /internal to the Internal Tool backend at 127.0.0.1:8082. Uses shared Base, Components and Styles with project-owned session, navigation and domains. No School imports or direct Platform requests. Install from frontend/ with pnpm --filter @groovehub/internal-tool... install --frozen-lockfile; run pnpm --filter @groovehub/internal-tool dev/build/test from frontend/. Root Makefile provides internal-frontend-* convenience targets. Configure backend INTERNAL_TOOL_ALLOWED_ORIGIN=http://127.0.0.1:4174, run migrations and bootstrap an operator first. Production requires its own HTTPS origin and same-origin /internal ingress. Never rewrite Secure cookies to support plain HTTP; use browser-supported loopback or HTTPS.

Screens: login, requests, approval inbox/bulk approval, template registry, environments, operators, local workflow history. Supports request detail, approve/reject/cancel/execute and reconciliation. L2-only navigation and actions are presentation controls; backend authorization remains authoritative. New request selectors load paginated registry entries up to 1,000 per resource; oversized catalogs fail closed. Request inputs use schema-driven top-level scalar controls and explicit omit/null modes, with JSON editors for nested objects and arrays. The serializer preserves exact numeric text on submission; backend validation remains authoritative. Template schema authoring still uses JSON. Registry, requests, approvals, operators and history use the shared universal Table with server pagination and stable column IDs; login has a shared form, responsive brand templates, dedicated hook, literal copy constants and a scoped CSS Module. Recursive nested field editing, remaining page decomposition, full guideline verification and browser E2E are subsequent work. The pnpm workspace and lockfile live under frontend/ until the libraries are published. No root-level package manager or Go workspace is required.

The L2 Audit page offers local history, centralized operator history, delivery counts and blocked-event requeue confirmation. Central history requires configured read-only backend credentials. Requeue retains original occurrence identity and does not correct an invalid payload. Refresh is manual; no browser-level audit workflow verification has been performed.

Request creation now loads the caller's school grant catalog. School templates, environments and school IDs are filtered by exact requester grants, and changing a template or environment clears the downstream selection. The read-only pilot's schoolId input is derived from the selected authorized school. Global registry proposals are unchanged. UUID labels are used because no authoritative school directory is available. The backend still permits unbound proposals through direct API calls; these cannot execute. The UI intentionally offers only configured school request targets.

When the backend's School directory reader is configured, authorized school options include canonical school names and codes. Missing/disabled schools are omitted. In UUID-only development mode the selector retains UUID labels. A directory outage with reader configured fails the registry load rather than silently presenting stale choices.

School rename requests display the authoritative current school name and version and bind them into the immutable request snapshot. The new name remains an editable schema field. Versions are decimal strings on the grant API so JavaScript cannot round int64 identifiers. The schema serializer writes the exact integer into the approved input. Reopen the request form to refresh an outdated snapshot.
