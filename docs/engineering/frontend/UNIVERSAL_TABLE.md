# Universal Table — Phase 2.1 implementation status

The initial shared Table, immutable Column builder, Filters, Sort, QuickFilters, Pagination, local and async selections, and responsive Sheet have been implemented. The design extends the existing Login theme tokens with a common control radius and heights. Desktop dialogs and mobile sheets share state.

User Setup is registered at /users/setup. The verified account API supports search, invitation-based creation, username update, lifecycle transitions, and invitation resend. Account search accepts one sort; email is filterable but not sortable. Verified statuses are PENDING_SETUP, ACTIVE, SUSPENDED and DEACTIVATED. Primary role (single Select) and secondary roles (MultiSelect) are provided as a reusable UserRoleFields component; actual role assignment must wait for server-owned role lookup and persistence APIs. No status or password is editable in the user form.

Filter UX: manage -> add/edit -> field selector -> operator -> value -> save draft -> apply. No applied chips are rendered on the table page.

Outstanding: full anchored popovers, calendar engine and timezone-aware date/time, option-label resolution and virtualization, client-side and advanced table engines, column resizing/pinning/reordering/persistence, bulk selection, full mobile card renderer, backend role and personal detail integration, and production validation. The existing architecture gates remain required; this is incremental source work, not release certification.

## Compact mobile list and infinite loading

At phone widths the universal table uses a title with icon-only create action, no desktop description, a full-width search and a single options button. Filter, sort, table settings, batch-size and refresh controls live in the options sheet; refresh closes it. Existing filter/sort editors remain bottom sheets. The optional `mobileRowProps` supplies a domain-owned compact row renderer, click and row actions; the table owns list layout, keyboard activation and scrolling. `mobileInfiniteProps` is opt-in and represents backend cursor loading; automatic intersection loading calls `LOAD_MORE`, with an explicit retry/load-more fallback. No numbered pagination appears in this mode. Search/filter/sort/batch changes reset the query and scroll position; the owner accumulates unique server rows and stops when there is no next cursor. Desktop pagination stays unchanged. Fill-workspace pages reserve bottom navigation space and scroll the list instead of the entire page. User Setup mobile rows show username/email and status without repeating column labels or timestamps; account details show the timestamps.

Compact User Setup rows use a 32px avatar, a single-line username and email, and a small plain semantic status beside the username. Long emails are truncated in the list; the full value remains available in account details. Mobile infinite lists render only active loading and load-more/retry controls, with no end-of-list record counter or empty footer. Desktop status pills and pagination remain unchanged.
